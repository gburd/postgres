# Option A on libxtc v1.40.3: io_del_fd race FIXED (confirmed), collapse persists via a task->state cross-loop race

Date 2026-08-30 (mala c6id NVMe; PG debugoptimized + a TSan build, libxtc v1.40.3 rev d0adff7e).

## v1.40.3 fixed what I reported (validated)
- __xtc_io_defer_del_fd (owner-routed fd unregister) + reap-own-io-before-steal: BOTH
  compiled in.  TSan: the xtc_io_del_fd/__find_fd/io->fds race went 139 reports -> 0.

## But the concurrent-commit collapse PERSISTS
- 64/192/256-client TPC-B write (fibers, fsync on): still collapses to ~0 tps after ~2s.
- native AND forced-offload both collapse (0-2 nonzero samples/15).
- gdb unchanged: WALWriteLock HELD EXCLUSIVE (0x80042000) by an off-thread fiber, ~30 loops
  idle in xtc_io_poll, commits frozen.

## Root cause of the residual (fresh TSan run on v1.40.3)
A NON-ATOMIC cross-loop data race on task->state (and the run-queue link) between a loop's
inbox XTC_INB_WAKE handler and the task's owning loop's dispatch:
  WRITE  __xtc_loop_step loop.c:637  t->state = XTC_TS_RUNNING           (loop T48, dispatch)
  PREV   __xtc_inbox_drain loop.c:137 m->task->state = XTC_TS_SCHEDULED   (loop T46, WAKE)
  + queue-link loop.c:834 vs __xtc_loop_enqueue loop.c:357.
task->state is a plain int written non-atomically from both the owning loop (dispatch) and
a peer loop draining a cross-thread WAKE for that task (work-steal/rebalance ownership
ambiguity).  The wake_pending latch beside it IS atomic (loop.c:146) but the state store is
not -> corrupted state/queue -> the WALWriteLock-holder fiber's wake is lost -> stranded ->
collapse.  Filed: plan_docs/phase16_audits/LIBXTC_V1403_TASK_STATE_CROSS_LOOP_RACE.md.
Ruled out (same run): io_del_fd (gone), ProcWakeSemaphore (spinlock-blind FP), hot-cells,
lock.c/dlist/liburing (benign).

## Status
Option A model still correct; single-fiber cases all fixed; io_del_fd fixed.  Default flip
stays BLOCKED on this task->state cross-loop race (the 4th in the cross-loop-step family:
v1.39 producer-nudge, v1.40.2 done-flag, v1.40.3 fd owner-routing, now task->state).  Fix
direction filed: make state atomic w/ CAS in the WAKE handler, or owner-route the
WAKE state-change+enqueue (as v1.40.3 did for the fd registry).  fork baseline ~45.6k tps.
