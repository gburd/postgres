stackless scheduler on the strength of these results.

## Compile failures and repairs

The untouched baseline failed in `launch_backend.c`:
`ActiveInjectionPoints` was undeclared in save/restore backend variables.
Its declaration used `EXEC_BACKEND`, while its definition's `NON_EXEC_STATIC`
and consumers use `FORKEXEC_BACKEND`. Align the declaration guard, retaining
static linkage where neither exec backend nor process fallback is built.

That repair exposed a second compile failure in the runtime GUC test:
`Array_nulls` was undeclared. Upstream commit `e96efd07c7` removed `array_nulls`;
remove the leftover runtime field, defaults, accessor definitions/prototypes
and test references. Other GUC checks remain intact.

After both repairs, discard PG build outputs, rebuild and reinstall backend
and test modules together. Candidate diff SHA256 (seven source files):
`90a2ee9b1aa72ab2b993b7bcf9ff55485615e547f9553a43ba04b926b58d6585`.

## Full fiber regression stall

The four-loop fiber/sync run emitted 41 test verdicts and then stopped advancing
in the third parallel group. The outstanding test was `database`, executing
`ALTER DATABASE regression_utf8 SET TABLESPACE regress_tblspace`. A monitor
query remained responsive and showed `IPC / ProcSignalBarrier`; autovacuum also
continued working. This was not evidence of an entirely stalled executor.

A stopped-process slot capture showed global barrier generation 3. Logical
replication launcher backend 4 remained at generation 2 with check mask 1;
other live participants were at generation 3. A later registry capture showed
the launcher's real interrupt mailbox mask 128, latch `is_set=1` and
`maybe_sleeping=1`, and owner fiber `3.1.1` still parked on fd 382. The slot's
separate interrupt mask being zero does not mean its mailbox was consumed.

`SetLatch`'s same-OS-thread routing is a source-level suspect: distinct fibers
on one loop own distinct selfpipes, but that path uses `WakeupMyProc` and
suppresses the explicit owner-fiber wake. A controlled reproducer is required
before attributing this stall to that path.

After roughly eight minutes, the investigator terminated the regression runner,
then the harness captured state and stopped the server cleanly. This run is
aborted red, not a completed suite or an outer-timeout result. No second full
run was attempted. Early and pre-cleanup captures include tail/rings/procs,
thread stacks, activity and fdinfo; event eviction prevents absence claims.
A saved parked-fiber stack was not obtained.

Focused evidence: `evidence-fiber-initial`. Full-run evidence:
`evidence-full-fiber1`, archive SHA256
`97fb615347e9518eb739b50b8ee510bc16aa2e52dd66f4b530dbc0a947dd23ef`,
under the same scratch ledger. No test servers remain from those runs.

Workers, TLS, cancellation, crash handling, full regression and connection churn
remain unqualified. The hard-wait-error-as-wake policy and ownership failures
remain open. These focused passes do not prove the historical fiber stalls
resolved, and stages 2–4 have not begun.
