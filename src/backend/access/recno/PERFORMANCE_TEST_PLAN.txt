1. Executive Summary
===================

This document outlines a comprehensive performance testing plan for the RECNO
storage access method, designed to validate its performance characteristics
against PostgreSQL's heap storage across diverse workloads, scales, and
configurations. The plan encompasses functional validation, performance
comparison, scalability assessment, and stress testing of RECNO's key features:

- Time-based MVCC with in-place updates
- Integrated compression system
- Overflow page management
- Advanced space management and defragmentation
- WAL-based UNDO/REDO recovery

The testing plan is designed to provide definitive answers about when and where
RECNO provides benefits over heap storage, identify performance limits, and
validate production readiness across a wide range of real-world scenarios.

2. Testing Objectives and Success Criteria
==========================================

2.1 Primary Objectives
----------------------

**Objective 1: Storage Efficiency Validation**
- Demonstrate 30-50% reduction in storage bloat for update-heavy workloads
- Validate 15-30% storage reduction through compression on text-heavy data
- Prove overflow pages provide better space efficiency than TOAST
- Success Criteria: Achieve target storage reductions across representative workloads

**Objective 2: Update Performance Validation**
- Demonstrate 2-3x faster update performance through in-place updates
- Validate reduced WAL volume for updates (40-60% reduction)
- Prove stable TID benefits for index performance
- Success Criteria: Achieve target performance improvements on update-heavy workloads

**Objective 3: Maintenance Overhead Reduction**
- Demonstrate 5-10x faster VACUUM operations
- Validate 70-80% reduction in VACUUM frequency requirements
- Prove opportunistic defragmentation effectiveness
- Success Criteria: Achieve maintenance overhead reductions with comparable data quality

**Objective 4: Feature Performance Validation**
- Validate compression provides net performance benefit despite CPU overhead
- Demonstrate overflow pages outperform TOAST for large attribute access
- Prove time-based MVCC scales better than XID-based MVCC
- Success Criteria: Each feature provides measurable performance benefit

**Objective 5: Scalability and Limits Assessment**
- Identify performance limits under extreme conditions
- Validate behavior under resource constraints
- Assess scaling characteristics from small to very large datasets
- Success Criteria: Understand operational limits and scaling behavior

2.2 Secondary Objectives
------------------------

**Reliability and Consistency**:
- Validate crash recovery performance and correctness
- Ensure consistent performance across different hardware configurations
- Verify performance stability over extended test periods

**Ecosystem Integration**:
- Validate performance with various PostgreSQL features (indexing, partitioning, etc.)
- Test integration with PostgreSQL tools and utilities
- Assess impact on backup and restore performance

**Operational Readiness**:
- Validate monitoring and diagnostic capabilities
- Test performance under various configuration parameters
- Assess learning curve and operational differences from heap

7. Comparison Methodologies
==========================

7.1 Baseline Establishment
--------------------------

**Heap Storage Baseline**:
For each test scenario, establish equivalent heap storage baseline:

1. **Identical Schema**: Create identical table structures using heap storage
2. **Identical Data**: Use same data generation seeds for reproducible datasets
3. **Identical Configuration**: Use same PostgreSQL configuration parameters
4. **Identical Hardware**: Run all tests on same hardware configuration
5. **Identical Timing**: Account for system load variations, run tests at same times

**Baseline Measurements**:
- Storage space utilization (table + indexes + TOAST)
- Query performance (latency and throughput)
- Update performance and storage bloat over time
- Vacuum performance and frequency requirements
- Memory and CPU utilization patterns
- I/O patterns and efficiency

7.2 Performance Measurement Standards
------------------------------------

**Timing Methodology**:
- Use PostgreSQL's built-in timing capabilities where possible
- Multiple test runs with statistical analysis (mean, median, std dev)
- Warm-up periods to account for cache effects
- Cool-down periods between tests

**Resource Monitoring**:
- System-level monitoring (CPU, memory, I/O, network)
- PostgreSQL-level monitoring (pg_stat_*, pg_statio_*)
- RECNO-specific monitoring functions
- Application-level timing measurements

**Statistical Analysis**:
- Minimum 5 test runs per scenario
- Statistical significance testing (t-tests, confidence intervals)
- Outlier detection and handling
- Performance regression analysis

7.3 Fair Comparison Guidelines
-----------------------------

**Configuration Parity**:
- Use optimal configurations for both heap and RECNO
- Account for different tuning requirements
- Document configuration differences and rationale

**Workload Equivalence**:
- Ensure identical logical operations
- Account for different physical storage patterns
- Validate data integrity between storage methods

**Feature Compensation**:
- Compare RECNO compression vs external compression for heap
- Compare RECNO overflow vs TOAST performance
- Account for different maintenance requirements

8. Performance Metrics and Data Collection
==========================================

8.1 Primary Performance Metrics
-------------------------------

**Storage Efficiency Metrics**:
```sql
-- Storage space measurements
SELECT
    schemaname,
    tablename,
    pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) as total_size,
    pg_size_pretty(pg_relation_size(schemaname||'.'||tablename)) as table_size,
    pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename) -
		   pg_relation_size(schemaname||'.'||tablename)) as external_size,
    n_tup_ins, n_tup_upd, n_tup_del,
    CASE WHEN n_tup_ins > 0
	 THEN pg_total_relation_size(schemaname||'.'||tablename) / n_tup_ins
	 ELSE 0 END as bytes_per_tuple
FROM pg_stat_user_tables t
JOIN pg_tables ON t.tablename = pg_tables.tablename;

-- RECNO-specific storage metrics
SELECT
    tablename,
    (recno_compression_stats(tablename)).avg_compression_ratio,
    (recno_overflow_stats(tablename)).total_overflow_pages,
    (recno_fsm_stats(tablename)).pages_needing_defrag
FROM pg_tables WHERE tablename LIKE 'recno_%';
```

**Performance Timing Metrics**:
```sql

-- Insert performance
```

**Continuous Monitoring**:
```python
#!/usr/bin/env python3
"""
Continuous performance monitoring for RECNO tests
"""
import psycopg2
import time
import json
from datetime import datetime

class RecnoPerformanceMonitor:
    def __init__(self, connection_string):
	self.conn = psycopg2.connect(connection_string)
	self.metrics = []

    def collect_metrics(self):
	cur = self.conn.cursor()

	# Collect standard PostgreSQL metrics
	cur.execute("""
	    SELECT
		schemaname, tablename, n_tup_ins, n_tup_upd, n_tup_del,
		n_tup_hot_upd, vacuum_count, autovacuum_count,
		pg_total_relation_size(schemaname||'.'||tablename) as total_size
	    FROM pg_stat_user_tables
	""")

	pg_metrics = cur.fetchall()

	# Collect RECNO-specific metrics
	cur.execute("SELECT * FROM recno_mvcc_stats()")
	mvcc_stats = cur.fetchone()

	# Store metrics with timestamp
	metric_snapshot = {
	    'timestamp': datetime.now().isoformat(),
	    'pg_metrics': pg_metrics,
	    'mvcc_stats': mvcc_stats
	}

	self.metrics.append(metric_snapshot)

    def run_monitoring(self, duration_seconds, interval_seconds):
	start_time = time.time()
	while time.time() - start_time < duration_seconds:
	    self.collect_metrics()
	    time.sleep(interval_seconds)

    def save_results(self, filename):
	with open(filename, 'w') as f:
	    json.dump(self.metrics, f, indent=2)
```

**Statistical Analysis Methods**:
```python
import numpy as np
import scipy.stats as stats
import matplotlib.pyplot as plt

class PerformanceAnalyzer:
    def __init__(self, heap_results, recno_results):
	self.heap_results = np.array(heap_results)
	self.recno_results = np.array(recno_results)

    def calculate_improvement(self):
	"""Calculate percentage improvement of RECNO over heap"""
	heap_mean = np.mean(self.heap_results)
	recno_mean = np.mean(self.recno_results)

	improvement = (heap_mean - recno_mean) / heap_mean * 100
	return improvement

    def statistical_significance(self, alpha=0.05):
	"""Test statistical significance of performance difference"""
	t_stat, p_value = stats.ttest_ind(self.heap_results, self.recno_results)
	significant = p_value < alpha

	return {
	    't_statistic': t_stat,
	    'p_value': p_value,
	    'significant': significant,
	    'confidence_level': (1 - alpha) * 100
	}

    def confidence_interval(self, confidence=0.95):
	"""Calculate confidence interval for performance improvement"""
	diff = self.heap_results - self.recno_results
	mean_diff = np.mean(diff)
	se_diff = stats.sem(diff)

	interval = stats.t.interval(confidence, len(diff)-1,
				  loc=mean_diff, scale=se_diff)
	return interval

    def generate_report(self):
	"""Generate comprehensive performance analysis report"""
	improvement = self.calculate_improvement()
	significance = self.statistical_significance()
	ci = self.confidence_interval()

	report = f"""
	Performance Analysis Report
	==========================

	Mean Performance Improvement: {improvement:.1f}%
	Statistical Significance: {'Yes' if significance['significant'] else 'No'}
	P-Value: {significance['p_value']:.4f}
	95% Confidence Interval: ({ci[0]:.1f}%, {ci[1]:.1f}%)

	Heap Results: μ={np.mean(self.heap_results):.3f}, σ={np.std(self.heap_results):.3f}
	RECNO Results: μ={np.mean(self.recno_results):.3f}, σ={np.std(self.recno_results):.3f}
	"""

	return report
```
